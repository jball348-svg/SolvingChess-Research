### New baseline calibration

The new implementation is explicitly RP1 code, not a reconstruction of missing
R2/R4/R5 programs. Its primary task is White's forced mate within six plies in a
restricted rectangle. The development arena is 3×4 KRK. A complete, separately
implemented layer DP enumerated **1,142 valid KRK states and 3,964 edges**;
598 states satisfy this bounded mating proposition. Its six propagation passes
examined 23,784 edges. Search and DP share move/state semantics, which limits
their independence.

All eight development queries agreed with the complete DP in all three repeats:
five positive and three negative bounded answers; no timeouts or unknowns.
The reserved larger domains were neither enumerated nor solved.

Work counts, query digest, certificate digests and serialized table size were
identical across repeats. Complete smoke-command CPU times were approximately
0.416, 0.428 and 0.427 seconds, including query generation and the optional full

These timings calibrate feasibility and instrumentation only. They establish
ordinary cache behaviour, **not a fixed-library or cumulative discovery gain**.

### Checks, corrections and accounting limits

Fourteen targeted checks pass. They cover move generation, warm caching, positive
and dual-negative certificates, omitted Black replies, false targets, invalid
depth/cycles, clock/intended claims, legal repetition histories, invalid history
merges, mate-at-150 precedence, lower-material capture and template/cache guards.
The final process envelope includes the complete test output.

The first negative-control test incorrectly assumed that a hand-picked Black
position was winning for White within six plies. The exact checker rejected the
expected proposition. The fixture was replaced with an already observed positive
development query containing two Black replies; the omission test then correctly
rejected the edited certificate. The original failed test output is preserved in
`evidence/checks-initial.txt`. This was a pre-freeze fixture correction, not a
benchmark change. An unavailable `/usr/bin/time` caused one shell command to fail
before compilation; the replay driver uses Python resource accounting instead.
A preliminary single synthetic-control solve was also run before the consolidated
smoke. No failed evaluation or candidate discovery is being omitted.

The final seam also trims a template's required horizon to its actual proof
height; a test confirms that this proof can be used after some plies have been
spent. No new target was searched to choose that change.

Measured calibration consumed roughly 33 CPU seconds, far below RP1's one-hour
allowance. Small preliminary shell/check activity and package installation were
not fully metered. LLM design/implementation time and historical discovery costs
are unavailable, not zero. No monetary/total-human-effort advantage is claimed.
There are no engines, paid services, inherited truth stores or late-review source
dependencies. The environment used Python 3.12.14, chess 1.11.2 and GCC 13.3.0.
The new checker still trusts the shared model and python-chess; it is not a Lean
formalization or independently validated full-rules chess engine.

### Contract and execution machinery

All 13 source-manifest files match RP1 commit
`ccf3a1c18ac9f92250bb94576a9d3f010fab80f3` byte-for-byte. The intervening
`68539fd` commit changes documentation only. The pinned chess 1.11.2 core hash
also matches. RP1 solver, checker, model, generator, reuse seam, protocol and
archive are unchanged.

`src/rp2.py`, `rp2_support.py` and `rp2_campaign.py` add the mechanical enumeration,
measurement and generic-cache comparator. F/G lookup uses the frozen index and
candidate order. Instrumentation wraps the existing checker and reads its
partial counters on exceptions; it changes no acceptance condition. C retains
the full domain and the full positive/negative witness, transforms it only under
a matching domain symmetry, and checks it before import. Each candidate is
compiled/checked even when duplicate or over the object cap. C visits all root
and subproof nodes, including negative and terminal nodes, in breadth-first UCI
order. A serialized nonfitting entry would be rejected without eviction; the
byte limit was never reached. No RP2 heuristic revision or candidate editing
occurred.

Eighteen controls pass: the unchanged 14 RP1 controls and four additional tests
of comparator symmetry/negative certificates, subproof extraction, failed-check
accounting and equivalence of instrumented versus frozen proof lookup. New tests
use RP1 synthetic fixtures only, never experimental library seeds. An initial
new test wrongly required a tiny CPU interval to be strictly positive; the clock
can quantize to zero, so the test now accepts zero CPU and requires positive wall
time. Both the failed test and final passing run are retained. Two earlier import
failures arose before the dependency was available in this resumed execution
environment. They did not execute any donor or reserved query.
