# Review session template

## Session ID
`R?-S?`

## Question
One sentence describing the viability question being tested.

## Candidate bridge/scaling proposition
State one falsifiable proposition with explicit hypotheses and conclusion. If none can be stated, record that fact.

## Inherited facts allowed
List exact repository claims being treated as inputs and their source paths.

## Attack plan
Describe the strongest attempted falsification: countermodel, hostile prospectively frozen arena, proof obstruction, lower bound, external benchmark, or scaling experiment.

## Work performed
Commands, artifacts, derivations, hardware/runtime context and deviations.

## Result
`SURVIVED`, `FAILED`, `PARTIAL`, or `NO_CANDIDATE`.

## Scope
What exactly was established or killed; what was not.

## Obligations retired / created
Name relevant review obligation or audit-issue IDs.

## Strike
`YES` or `NO`, with reason under `REBOOT_CRITERIA.md`.

## Next discriminating step
Only the smallest step justified by this result.

## Source/provenance updates
Paths, hashes and external citations added to the review.
