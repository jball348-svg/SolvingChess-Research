# The Plan from G10 Onward
*A dependency-ordered programme map from the G9 baseline to a machine-checkable White-non-loss proof*
LONG-RANGE ROADMAP | G10-G42 | SCIENCE + ENGINEERING + VERIFICATION + INTEGRATION
11 August 2026
> This is a dependency graph first and a numbering scheme second. The plan is intentionally longer than a near-term experiment list because the remaining problem is dominated by capabilities the current programme does not yet possess.
# 1. Planning principles
- Do not confuse increasing piece count with progress toward the initial position. Scale and connectivity must advance together.
- Complete rule semantics, independent move generation and durable verification before they become hidden dependencies of larger computations.
- Treat symbolic compression as optional leverage, not a premise. A raw exact dependency is acceptable if it is typed, hashed and economically verifiable.
- Freeze candidate families and proof vocabularies before outcome inspection whenever a scientific transfer claim is being tested.
- Run explicit held-out falsification campaigns at regular intervals. Do not let a proof language become “universal” merely because the benchmark was selected around its successes.
- Build distributed/checkpointed infrastructure before jobs outgrow one session or one machine.
- A future contradiction of the requested White-non-loss endpoint is a scientific stop, not a failure to be hidden. If exact upstream work proves the initial position losing for White, the programme must report that and redefine 100 as the actual weak solution rather than forcing the requested theorem.

Distributed infrastructure (G13) and proof storage (G14) should run in parallel after G11. History-dependent draw scaling (G20) can advance alongside 9-10-man solving (G17). The raw exact-truth carrier (G18) is deliberately early because it is the fallback dependency for every later stage where symbolic compression fails.

# 4. Detailed stage map
## G10 - Final Chess Ruleset and State-Semantics Contract
Mission: Freeze the exact game that 100% is supposed to prove.
Why this stage exists: Rules/model completeness is only about 20/100 in the G9 assessment; later scale work cannot safely proceed on a provisional state definition.
Dependencies: G9 baseline and frozen historical model caveats.
Primary research / engineering questions:
- What state variables are required for castling rights, en passant rights, repetition identity, 50/75-move counters and claim semantics?
- How will legal historical reachability be represented or safely separated from static board validity?
- What exact outcome convention is used for automatic draws, claimable draws, dead positions, checkmate and stalemate?
Expected deliverable / proof artifact: Versioned formal state schema, legal terminal/draw semantics specification, canonical position identity and transition contract for the final programme.
Advance / stop condition: Advance only when every rule/state variable has an explicit machine-readable meaning and test cases. Stop if the programme cannot state one unambiguous ruleset; do not begin larger “final-model” computations.
Unlocks: G11, G12, G20, G35
Primary category: Formal verification / rules science
## G11 - Independent Move-Generation and State-Conformance Suite
Mission: Build two genuinely independent implementations of the G10 state and move rules and force them to agree.
Why this stage exists: G8 verification is strong but still relies on the same broad software lineage; full-chess correctness requires a repository-quality legality oracle.
Dependencies: G10.
Primary research / engineering questions:
- Can state identity and successor/predecessor generation be cross-checked exhaustively on small domains and statistically/adversarially on larger ones?
- Can every special-move and history transition be round-tripped?
- Can malformed or historically impossible states be rejected deterministically?
Expected deliverable / proof artifact: Reference move generator, independent conformance generator, differential test corpus, fuzz/property tests and zero-mismatch ledger.
Advance / stop condition: Advance on zero unexplained mismatches across the frozen suite. Any unexplained legality mismatch is blocking.
Unlocks: G12-G15, all future exact solves
Primary category: Solver engineering / verification
## G12 - Full-Rule Small-Arena Certification
Mission: Re-solve a compact but varied regression portfolio under the complete G10/G11 state semantics.
Why this stage exists: The project has many restricted-model truths; it needs anchors that exercise the final rule state before scale is increased.
Dependencies: G10-G11.
Primary research / engineering questions:
- Which small arenas actually exercise repetition, move-count claims, dead positions, promotions, captures and special rights?
- How do older restricted results map into the new state semantics without silently rewriting history?
Expected deliverable / proof artifact: A frozen “final-rules reference suite” with truth hashes, independent move-generation agreement and standalone certificate replay.
Advance / stop condition: Advance when selected arenas are independently reproduced under the final rules. Historical Pilot-G8 numbers remain historical where models differ.
Unlocks: G15-G22
Primary category: Science + verification
## G13 - Distributed and Checkpointed Exact-Compute Platform
Mission: Make exact solving resumable, deterministic and multi-machine before state growth makes one-session runs fragile.
Why this stage exists: The G9 gap map identifies distributed/checkpointed computation as a prerequisite, not an afterthought.
Dependencies: G11; can begin in parallel with G12.
Primary research / engineering questions:
- How are material-signature jobs partitioned without changing semantics?
- How are checkpoints, retries, work ownership and deterministic merge handled?
- How is the full run reproducible from a manifest?
Expected deliverable / proof artifact: Content-addressed job manifests, checkpoint format, deterministic scheduler, retry/recovery protocol and reference distributed run.
Advance / stop condition: Advance when killing/restarting workers reproduces identical truth/certificate hashes. Stop on nondeterministic merges or hidden global state.
Unlocks: G17 onward
Primary category: Solver engineering
## G14 - Proof Store and Content-Addressed Dependency Graph
Mission: Create a durable repository for exact truth tables, sparse proof objects, arena declarations and dependency identities.
Why this stage exists: Long proofs will reuse thousands or millions of subgames; ad hoc files will not scale or remain auditable.
Dependencies: G11; coordinate with G13.
Primary research / engineering questions:
- What is the immutable identity of a solved material signature?
- How are semantic versions, ruleset versions, source hashes, truth hashes and certificate hashes linked?
- How are superseded artifacts retained without being accidentally reused?
Expected deliverable / proof artifact: Proof-store schema, dependency index, provenance graph, garbage/supersession rules and portable bundle format.
Advance / stop condition: Advance when any proof object can resolve every dependency by immutable identity and reproduce the exact declared model.
Unlocks: G15 onward
Primary category: Engineering / preservation
## G15 - Verifier Hardening and Formal Core
Mission: Shrink the trusted computing base and make proof checking independent of the producer and scalable enough to remain meaningful.

Dependencies: G10-G14.

- How can reverse-graph memory use be reduced?

Advance / stop condition: Advance when producer/verifier separation is demonstrably real and hostile certificate mutations are reliably rejected.
Unlocks: All later stages, especially G27 and G41

# 5. Major roadmap branches and contingency logic
- If symbolic compression weakens sharply: Do not force new grammars. Use G18 raw exact dependencies and G28 hybrid planning; focus research on compute, sharing and local verification economics.
- If exact scale stalls before 10-12 man bridges: Freeze the boundary prospectively, then improve G13/G17 algorithms or choose structurally meaningful decompositions. Do not shrink arenas after outcome inspection to manufacture a pass.
- If automatic discovery fails: Retain assisted discovery as an explicit human-in-the-loop cost and measure it. The roadmap can still proceed, but long-range labour/description economics worsen and the road-to-100 score should be revised downward.
- If verification becomes more expensive than recomputation: Allow verifier strategies that re-solve small dependencies while checking large ones locally. Certificate bytes and verification compute remain separate optimization objectives.
- If middlegame held-outs break the current proof language: Return to G23-G33 and add new typed object classes only when old classes plus guards/subsumption genuinely cannot represent the proof. Preserve counterexamples.
- If the initial-position connector finds no intersections: Do not brute-force the opening indefinitely. Use the failed frontier to prospectively choose new bridge domains that move the basin network toward the actual forward tree.
- If exact analysis proves White is losing: The requested “White cannot lose” 100-point endpoint is falsified. Freeze the counter-proof, redefine the final objective as the actual weak solution/value, and do not conceal the contradiction.

# 7. What counts as real progress after G9
The roadmap is designed so that later programme numbers are not automatically “closer to 100.” A stage moves the programme forward only when it closes a named capability gap with an exact artifact or a clean falsification/tractability boundary. In particular, another attractive restricted arena does not materially move the headline score unless it improves rules completeness, scale law, breadth, discovery, composition, verification, basin connectivity or initial-position reach.
The first future event likely to change the strategic character of the programme is not “nine pieces.” It is the first machine-checkable connection from the standard initial position into a reusable certified basin network. Before that moment the project is building the road; after that moment it is closing the remaining lanes.
